Questions, answered

The small print, in plain words.

Everything you might reasonably want to know before handing us a file. Short answers, no legal fog.

Are my files uploaded to a server?

No. File-based tools read the file in your browser and write the result in your browser. There is no upload endpoint in this build. The only tools that contact a third party are the YouTube and Instagram downloaders, and they send only the public link you paste.

Does it work offline?

After the first visit, the service worker caches the interface and the vendored engines, so file tools keep working without a connection. The downloaders need the internet because Loader.to does the fetching.

Why do the downloaders use a partner API?

YouTube and Instagram do not expose a browser-only download endpoint. Loader.to provides the download card in a new tab. Your public link is shared with that provider; no file, account or password is. Please save only content you own or have permission to keep.

Can this unlock a password-protected PDF?

Only when you already know the password. The Unlock tool removes protection from a document you can already open; it does not guess, crack or bypass passwords. Other PDF tools will ask you to unlock a protected file first.

Are the outputs watermarked or limited?

No. There is no watermark added by the hub, no export quota and no paid tier. A tool may add a watermark only when you ask it to. Your only practical limit is the memory and speed of your own device.

Which browsers are supported?

Current Chrome, Edge, Firefox and Safari releases. Some media features depend on MediaRecorder and Web Audio support, which varies by browser. If a capability is missing, the tool says so instead of failing silently.
